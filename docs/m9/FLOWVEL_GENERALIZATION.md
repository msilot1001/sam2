## 2. 왜 나빠지는가 (메커니즘 진단)

손실을 frame 종류로 나눴다. 기준은 직전 frame에서 FLOWVEL 출력이 있었는가다.

| 분할 | 추적 중 (직전 출력 있음: '+0.5 × 광류 속도' 작동) | 놓친 뒤 (직전 출력 없음: 광류 box 운반 작동) |
|---|---|---|
| dev | −16.8 | −26.2 |
| conf | −88.4 | −35.2 |

(단위: frame J&F 합)

- **두 성분 모두 손해다.** 하나만 고치면 되는 문제가 아니다. 그래서 '수정 1회'로 살릴 근거가 없다.
- **손실 위치:** GT가 비어 있는 frame에서는 거의 차이가 없었다(−6). 손실의 대부분(−161)은 대상이 보이는 frame에서 났다. 운동 추정이 작은 대상을 crop 밖으로 밀어내거나, 대상이 없는 동안 crop을 엉뚱한 곳으로 옮긴 결과다.
- **큰 손실 사례:** SGGL이 잘 추적하던 단위가 무너졌다.
  - 381hg4vf/obj1: 0.80 → 0.11
  - sjl7jcdm/obj1: 0.88 → 0.59
  - 1qjqdu64/obj1: 0.91 → 0.64
- **후속 조치:**
  - 같은 운동 성분을 포함한 JOINT(FLOWVEL + SCALE)는 실행하지 않는다. 사전 규칙: 더 나빠지는 방향으로 가지 않는다.
  - 값싼 운동(PCCARRY)은 우선순위를 맨 뒤로 내렸다.
