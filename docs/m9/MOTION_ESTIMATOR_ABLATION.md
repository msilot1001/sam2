# 값싼 운동 추정 비교 (RAFT vs 위상 상관)

- **질문:** M8의 광류 기반 crop 운반(RAFT-small)을 FFT 위상 상관 하나로 바꿀 수 있는가?
- **위상 상관 구현:** `src/spatial/motion.py` `phase_shift`
  - 1/4로 줄인 회색 영상에 Hann 창을 씌우고, 정규화 교차 전력 스펙트럼의 최댓값을 구한 뒤 부분 화소로 보정한다.
  - 학습된 가중치가 없고 GPU도 쓰지 않는다.

## 1. 추정값 일치 (오프라인, VOST 15단위 / 7영상, 연속 frame 1,634쌍)

- **명령:** `M9_DATA=data/m9 uv run python scripts/m9_motion_agree.py vost 15`
- **결과:** `outputs/milestone9/reports/motion_agree_vost.csv`
- **기준:** RAFT 카메라 운동, 즉 이전 frame GT box를 2배로 넓힌 영역 밖 광류의 중앙값이다.
  - GT는 대상 영역을 빼는 데만 썼다. 오프라인 비교용이며 온라인 arm은 GT를 쓰지 않는다.

| 분위 | 끝점 오차 (px) | RAFT 운동 크기 (px) | RAFT 지연 (s) | 위상 상관 지연 (s) |
|---|---|---|---|---|
| 25% | 1.5 | 7.1 | 0.053 | 0.003 |
| 50% | **3.1** | 13.7 | 0.056 | **0.004** |
| 75% | 6.1 | 30.9 | 0.095 | 0.007 |
| 90% | 14.9 | 62.9 | 0.099 | 0.007 |

- RAFT 운동이 5 px 넘는 1,407쌍에서 상대 오차 중앙값은 0.19다.
- 오차 2 px 미만은 34%다.
- 위상 상관은 RAFT보다 약 **14배 빠르다**(중앙값 0.004 s vs 0.056 s, 2080 기준).
- VOST는 1인칭 주방 영상이라 머리 운동이 크다(중앙값 13.7 px/frame).
- **해석:** 전역 이동은 대체로 맞춘다. 꼬리(상위 10%, 15 px 이상)는 회전·확대처럼 순수 이동이 아닌 운동이나 손 같은 큰 전경 운동에서 생긴다.

## 2. 인과 비교 (PCCARRY)

- **arm:** 출력이 비었을 때만 위상 상관 이동으로 crop을 옮긴다(23:13 고정).
- **실행 순서:** M8의 운반 성분(광류 box 운반)이 MOSEv2에서 해로웠다(놓친 뒤 frame 합계 dev −26.2, conf −35.2). 그래서 우선순위를 맨 뒤로 내렸고, Pod q3의 마지막 작업으로 MOSEv2에서 돌린다.
- **사전 기준:** FLOWVEL 효과의 70% 이상을 내면서 지연이 적어야 한다.
  - FLOWVEL 효과가 MOSEv2에서 음수(−0.0142)라서 이 기준은 의미가 없어졌다.
  - 대신 SGGL 대비 ΔJ&F와 −0.05 미만 단위로만 보고한다.
