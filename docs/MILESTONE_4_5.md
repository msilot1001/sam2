## 1. 동기

M1과 M4가 원래 가설에 두 가지 문제를 드러냈다.
- **문제 A (M1):** 카메라가 이동하는 프레임에서 pose-only와 recent-K가 같은 메모리를 고른다. 차이는 카메라가 정지한 구간의 미세한 pose 잡음에서만 생긴다.
- **문제 B (M4):** 30–50% random/burst(길이 4) 누락에서 평균 ΔJ&F는 −0.0021 ~ +0.0005였다. 새로 생긴 실패는 run 2개뿐이고, burst 393개 중 누락 직후 J < 0.5인 사건은 1개였다.

이번 단계의 질문: *SAM 2.1이 의미 있게 실패하는 현실적인 조건이 있는가? 그때 대안이 될 메모리가 실제로 있는가? 카메라 자세 기반 선택이 시간 기준 선택과 다른 메모리를 고르는가?*

## 2. SAM 2 메모리 동작 점검 (공식 코드 읽기만 함, 수정 없음)

`sam2_base.py::_prepare_memory_conditioned_features`, `sam2.1_hiera_t.yaml`

| 항목 | 공식 동작 |
|---|---|
| `num_maskmem` | 7 = 조건 프레임(prompt) + non-conditioning 메모리 최대 6개 |
| 조건 메모리 | `max_cond_frames_in_attn = -1`이므로 prompt는 **항상** 참조된다. 시간 위치 코드는 t_pos = 0 |
| non-conditioning 선택 | `memory_temporal_stride_for_eval = 1`이므로 **video index 기준 직전 6프레임**(`frame_idx−1 … frame_idx−6`)을 쓴다. 메모리를 고르는 단계가 따로 없다. 결과는 모두 `output_dict`에 쌓이지만 이 6개 외에는 참조되지 않는다 |
| 시간 위치 인코딩 | `maskmem_tpos_enc[num_maskmem − t_pos − 1]`. t_pos는 **수신 순번 차이**다 |
| object pointer | prompt와 직전 최대 15개 수신 프레임을 쓴다(`max_obj_ptrs_in_encoder = 16`). 위치값 = video index 차이 / 15, signed. `only_obj_ptrs_in_the_past_for_eval = true` |

**누락 후 시간 축이 어떻게 해석되는가:**
- M3/M4는 누락된 프레임을 빼고 수신 프레임에 0..N−1 번호를 다시 매긴다. 공식 SAM 2는 이 번호만 보므로, 원본으로 17프레임 떨어진 두 프레임(burst 16 직후)도 **바로 이웃한 프레임(t_pos 차이 1)으로 취급한다.** prompt까지의 거리도 원본 시간보다 짧게 보인다.
- 따라서 baseline은 원본 경과시간 정보를 전혀 받지 않는다. 계획서의 Δt(원본 frame 차이)는 지금 메모리를 *고르는* 데만 쓰이고, 모델 안의 시간 인코딩에는 반영되지 않는다.
- M5에서 정책을 구현하려면 선택한 메모리에 어떤 t_pos를 줄지(수신 순번 기준 vs 원본 시간 기준)를 따로 정해야 한다. 이는 계획서 §13의 '선택 후 메모리의 시간 슬롯 배치' 문제와 같다. 이번에는 바꾸지 않았다.

### pose 잡음 tolerance (`reports/N_pose_tolerance_sweep.csv`, `figures/N1_pose_tolerance_sweep.png`)

tolerance보다 작은 차이는 0으로 보고, 동률이면 최근 메모리를 고른다. 기본값 0은 원래 동작과 같다.

| tolerance | 정지 frame: pose-only ≠ recent-K | 이동 frame | 합성 데이터, 정지 + 지터(σ 5 mm, 0.02°) |
|---|---|---|---|
| 0 | 0.656 | 0.006 | 0.965 |
| 0.5 cm / 0.01° | 0.583 | 0.006 | 0.965 |
| 1 cm / 0.05° | 0.086 | 0.006 | 0.930 |
| **5 cm / 0.1°** | **0.063** | 0.006 | **0.005** |

**권장 tolerance: 5 cm / 0.1°.**
- **물리적 근거:** 정지한 VKITTI 카메라의 pose 변동 폭이 약 1.5 cm / 0.03°이다(M1). 실제 차량의 GNSS/VO 자세 오차는 보통 수 cm, 0.1° 수준이다. 이보다 작은 차이로 시야가 달라진다고 볼 근거가 없다.
- **수치적 근거:** 위 표에서 이 값을 넘으면 정지 구간 차이가 거의 사라지고, 이동 구간 차이는 바뀌지 않는다.
- 분할 결과를 보고 정한 값이 아니며, 정책을 확정하는 값도 아니다. 계획서 변경 사항이므로 멘토 확인이 필요하다.

## 7. 재방문 기하 연구 (PART D, **합성 기하만 사용**, 영상·분할 없음)

`src/memsel/synthetic.py`, `geometry/D_*.csv`, `figures/D1–D3`

| 궤적 (10 Hz 가정) | 속도 / 횡가속도 | 현실성 | 최소 재방문 간격 (≤ 2 m, ≤ 10°, age ≥ 21) | pose-only ≠ recent-K (L = 16 / 32 / 64 / 128) |
|---|---|---|---|---|
| 직진 | 10 m/s / 0 | 가능 | 없음 | 0 / 0 / 0 / 0 |
| 회전 R 15 m | 7.5 m/s / 3.75 m/s² | 가능 | 없음 | 0 / 0 / 0 / 0 |
| 정지 (정확) | 0 | 가능 | 21 (모든 frame) | 0 / 0 / 0 / 0 (전부 동률 → 최근) |
| 정지 + 지터 | 0 | 가능 | 21 | 0.97 / 0.97 / 0.97 / 0.97 (잡음, tolerance로 제거) |
| U턴 R 6 m | 4.5 m/s / 3.4 m/s² | 가능 | **없음** (같은 위치를 반대 방향으로 지나므로 시야가 다름) | 0 / 0 / 0 / 0 |
| loop R 5.1 m | 4.5 m/s / 3.97 m/s² | 가능 | **70** | 0 / 0 / 0 / **0.60** |
| loop R 15 m | 7.7 m/s / 3.95 m/s² | 가능 | **120** | 0 / 0 / 0 / **0.55** |
| loop R 5 m (비현실적) | 10 m/s / 20 m/s² | 불가능 | 31 | 0 / 0.66 / 0.68 / 0.68 |

- **해석적 하한:** 같은 위치와 같은 방향으로 돌아오는 가장 짧은 loop(R ≥ 5 m, 횡가속도 ≤ 4 m/s²)는 v = √(R·a) ≈ 4.5 m/s일 때 **약 70 frame**이다(10 Hz 가정).
- 따라서 **L = 32, 64로는 현실적인 재방문을 메모리 후보에 담을 수 없다.**
- 50% 누락이 있어도 L은 수신 frame 수로 세므로 64 수신 frame이 필요하다. 이 역시 L = 32를 넘는다.
- L = 32에서 정책이 갈라지게 하려면 10 m/s로 반경 5 m를 도는(2 g) 물리적으로 불가능한 궤적이 필요하다.
- U턴처럼 같은 장소로 돌아와도 반대 방향을 보는 경우는 시야가 비슷하지 않다. 앞쪽 카메라에는 재방문 효과가 없다.
- **L의 영향:** 재방문 효과는 L ≥ 128(원본 약 13초)이 되어야 나타난다. 계획서의 L = 32를 바꾸는 일이므로, 가설을 살리려고 L을 바꾸는 것은 이번 단계에서 하지 않았다.

## 10. 확인된 것과 확인되지 않은 것

**확인됨 (이번 실행의 측정 결과):**
- 길이 16 burst는 순정 SAM 2.1 Tiny에서 드물지만 치명적인 추적 상실을 일으키고, 상실한 대상은 거의 회복되지 않는다.
- 그 실패의 대부분은 메모리가 충분하고 정상 메모리도 참조 중인 상태에서 일어났다. 대상의 큰 외형 변화, 카메라의 큰 이동, 가림이 원인이었다.
- 자세 기반 선택은 이동 중에는 최근 선택과 거의 같고, 정지 중에는 잡음 때문에만 다르다.

**확인되지 않음:**
- 어떤 정책이 실제로 분할 정확도를 높이는지(M5의 범위).
- 시험 장면에서도 같은 양상인지.
- 실제 주행 데이터(KITTI-360)의 재방문 간격과 대상의 지속성.
- '대상이 보이는 정상 메모리를 일부러 유지하면 상실이 줄어드는지'.

**한계:**
- 개발 track 8개, 장면 2개이고 저하가 4개 track에 몰려 있다. CI는 n = 8 track 수준이다.
- 스트레스 조건은 탐색적이다.
- 정상 메모리 판정은 사후 GT로 했다.
- 10 Hz는 가정이다.
- 합성 궤적은 기하만 다룬다.

  1. 긴 누락(≥ 1.6 s) 후 상실을 줄이는 **시간 분산 / 상실을 고려한 메모리 유지** 정책이 recent-K보다 상실률과 회복률을 개선하는가?
  2. 누락 후 SAM 2의 시간 인코딩을 수신 순번 대신 원본 시간 기준으로 바꾸면 영향이 있는가? (§2의 문제)

- 어느 경우든 새 확인 실험의 규칙(누락 조건, L, tolerance, 주 지표)을 **시험 장면을 열기 전에** 고정해야 한다.
