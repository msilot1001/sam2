이번 단계의 범위:
- M3 manifest 96개(개발 track 8개 × 4조건 × 3 seed) 전체에 **순정 SAM 2.1 Hiera-Tiny**를 실행하고, 같은 원본 frame에서 M2 무손실 예측과 짝지어 비교했다.
- 메모리 선택기(M1)는 쓰지 않았다. 공식 코드·가중치·메모리 동작은 그대로다.
- 시험 장면(02/18/20)은 건드리지 않았다.
- **96/96 run이 완료되었고 모두 검증을 통과했다.**
- 이 단계는 자세 기반 선택의 효과를 시험하지 않는다.

## 2. Runner (`scripts/run_dropout_baseline.py`, `src/baseline/dropout_runner.py`)

각 run이 거치는 순서:
1. manifest 로드와 검증(CSV sha256, 구조 조건, 재생성 결과와 일치)
2. M2 기준과의 대응 검증
3. 수신 frame만 담은 clip 생성과 symlink 검증, 누락 이미지가 없는지 확인
4. 메모리 여유 확인
5. GT prompt 1회
6. SAM 2 추론
7. 원자적 저장: `predictions.npz`, `per_frame.csv`, `paired.csv`, `events.csv`, `latency.csv`를 쓰고, 마지막에 `record.json`
8. 저장 후 다시 검증

**재개:**
- 완료된 run은 다음이 모두 맞을 때만 건너뛴다: `record.json`, manifest sha, 모델 정보, 예측 파일 sha256과 frame id·shape, 지표 표가 수신 frame을 정확히 덮는지.
- 손상된 run은 `invalid/`로 옮긴 뒤(삭제하지 않음) 다시 실행한다.
- 실패는 `failures.jsonl`에 기록하고 다음 run으로 넘어간다.

**실제 실행 경과:**
- 첫 실행은 background 시간 제한 때문에 32/96에서 중단되었다(`Scene01_track063/burst_30_seed1` 추론 중).
- 결과 파일은 추론이 끝난 뒤에만 쓰므로 그 run의 흔적은 남지 않았다. 재개하자 그 run부터 다시 실행되었다.
- 이후 scene·track 단위로 나눠 실행해 96/96을 완료했다. 실패 0, invalid 0.

명령:
```bash
uv run python scripts/run_dropout_baseline.py --all              # 실행/재개 (순차)
uv run python scripts/run_dropout_baseline.py --scene Scene06 --track 12   # 일부만
uv run python scripts/run_dropout_baseline.py --all --status     # 검증만
uv run python scripts/run_dropout_baseline.py --all --eval-only  # 저장된 mask로 재평가
uv run python scripts/analyze_dropout_baseline.py                # 집계·그래프 → outputs/milestone4/
```

## 3. 집계 규칙

순서: frame → run(track × 조건 × seed) → track별 seed 평균 → scene(그 track들의 평균) → 개발 세트(8 track 평균).
- **track 가중치는 모두 같다**(M2와 같음). frame 수는 함께 기록하지만 가중치로 쓰지 않는다.
- delta = 누락 − 대응 무손실이다. 음수가 성능 저하다.
- 95% CI는 8개 track(seed 평균값)을 재추출한 bootstrap이다(10,000회, seed 0). n = 8이라 정밀도가 낮다.
- 장면이 2개뿐이라 계획서의 '장면 → track 계층 bootstrap'은 적용하지 않았다.

| random_50 | 972 | 3 / 1 | 3 / 1 | 3 / 1 | 0 / 0 |

| burst_50 | 964 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |

J < 0.5 기준으로 나눈 실패 유형:
- **A. 무손실에도 있던 실패(persistent):** 4 frame. 모두 Scene01 t86 frame 380(대상이 99% 가려진 37 px frame)이고, 그 frame이 수신된 run에서 무손실과 똑같이 실패했다.
- **B. 누락 run에서 새로 생긴 실패(new):** 6 frame, run 2개.
  - Scene06 t9 burst_30 s2, frame 74–77: J 0.03–0.06, 무손실은 0.96–0.98.
  - Scene06 t12 random_50 s1, frame 101: GT 1,200 px인데 예측이 비어 J 0. frame 118: GT 48 px 얇은 조각, J 0, 무손실은 0.59.
- **C. 무손실 실패가 누락 run에서 사라짐(resolved):** 0. 단, frame 380이 누락된 run에서는 그 frame이 비교 대상에서 빠진다. 이 경우는 '사라진 실패'가 아니라 '관측되지 않은 실패'로 따로 본다(예: burst_50 s0).
- **D. 실패 정도가 변함(severity_changed):** 0.
- **연속 실패 길이**(J < 0.5, 수신 순서 기준): 누락 run의 최대는 4(t9 burst_30 s2), 무손실 대응은 최대 1.

**새 실패의 원인 분석 (Scene06 t9 burst_30 s2, `figures/10a_case_worst.png`):**
- burst(70–73)가 prompt(69) 바로 뒤에 놓였다.
- 그 사이 트럭이 카메라 앞으로 들어오며 GT가 10,292 px(prompt) → 38,122 px(frame 74)로 약 4배 커졌다. 카메라는 정지 상태였다(이동 0.003 m).
- 누락 run은 메모리에 prompt frame 하나만 있는 상태에서, 운전석 부분(약 1.6–2.6k px)만 추적하고 새로 드러난 화물칸을 놓쳤다.
- 무손실 run은 점진적인 확대를 보며 전체를 따라갔다.
- 5번째 수신 frame(78)에서 J 0.98로 회복했다.
- 이 사례는 '짧은 누락 + 급격한 외형·크기 변화 + 메모리 부족'이 결합된 실패다. 카메라 자세 변화와는 무관했다.

| 항목 | burst_30 | burst_50 |
|---|---|---|
| burst 사건 | 144 | 249 |
| 관찰 구간 ≥ 2 / ≥ 5 | 125 / 90 | 180 / 76 |
| 관찰 구간 중앙값 | 6 | 3 |
| intact_at_first_frame | 123 | 180 |
| recovered_later | 2 | 0 |
| └ 그중 첫 frame에서 J < 0.5였던 사건(진짜 회복) | **1** (t9 s2, k = 5) | 0 |
| unrecovered_next_burst / unrecovered_end | 0 / 0 | 0 / 0 |
| insufficient_observation / no_observation | 16 / 3 | 60 / 9 |
| censoring 비율 (다음 burst로 / clip 끝으로) | 13.2% (15 / 4) | 27.7% (54 / 15) |
| 첫 frame에서 성능 저하(J < 0.5) / 추적 상실(J < 0.1) | 1 / 1 | 0 / 0 |
| 성능 저하 사건의 5프레임 이내 회복률 (분모) | 0.0 (1) | – (0) |
| 계획서 문구 그대로의 5프레임 이내 비율 (분모) | 0.989 (90) | 1.000 (76) |
| 누락 직후 첫 frame의 GT가 빔 | 3 | 2 |
| [보조] GT가 보일 때만 인정한 class: intact / recovered_later | 120 / 4 | 179 / 1 |
| 성능 저하 사건 중 같은 frame에서 무손실도 저하 | 0 | 0 |

- burst_30의 `recovered_later` 2건 중 1건(t86 s2, burst 375–378)은 첫 수신 frame은 정상이었다(J 0.82). 두 번째 수신 frame이 완전 가림 frame 380이라 J 0이 되었다. 무손실에서도 실패하는 frame이므로 누락에 의한 성능 저하에서 회복한 사건이 아니다.
- 성능 저하에서 회복한 사건은 t9 하나뿐이다. 회복 시작이 k = 5(원본 frame 차이 5)이므로 '5프레임 이내 확인' 기준으로는 실패다.
- **보이는 대상 기준 진단:**
  - burst 직후 대상이 완전히 가려진 사건에서는, 빈 예측이 DAVIS 관례상 J = 1을 받아 주 정의로는 intact가 된다.
  - GT가 보일 때만 인정하면 4건(모두 Scene06 t12 가림 구간)의 class가 바뀐다. burst_30 3건 중 2건은 recovered_later, 1건은 다음 burst 전까지 확인되지 않아 unrecovered_next_burst가 되었고, burst_50 1건은 recovered_later가 되었다.
  - 이 진단은 주 지표를 대체하지 않으며, 별도 열(`visible_class`)로 저장했다.

**censoring의 한계:**
- 계획서 문구 그대로의 5프레임 이내 비율(98.9%, 100%)은 관찰 구간이 5 이상인 사건(burst_30 90개 = 62.5%, burst_50 76개 = 30.5%)만 대상으로 한 값이다.
- 그 사건들의 거의 전부가 처음부터 정상이던 사건이다. 따라서 이 높은 비율을 '회복력'의 증거로 해석하면 안 된다. 회복이 필요했던 사건 자체가 거의 없었다.
- burst_50은 사건의 27.7%가 censoring되고(대부분 다음 burst가 바로 이어지기 때문), 관찰 구간 중앙값이 3이다. **현재 burst_50 설계로는 회복을 의미 있게 측정하기 어렵다.**
- 회복 분석만을 위한 민감도 실험으로, burst 간 최소 간격을 5 이상으로 둔 별도 패턴을 **제안한다**. 이번 주 실험에는 넣지 않았다.

## 7. 무엇이 취약성을 설명하는가 (사후 분석, GT·자세 정보는 분석에만 사용)

- **대상 크기:** 크기 구간별 평균 ΔJ는 모든 구간에서 |ΔJ| ≤ 0.005이다. 유일한 예외는 > 10,000 px 구간의 burst_30(−0.015)이고, 이는 t9 트럭 사례 하나 때문이다. 정확도 수준은 크기에 강하게 의존하지만(무손실 J: ≤ 500 px 0.78, > 10,000 px 0.98, M2와 같음), **누락으로 인한 변화는 크기와 뚜렷한 관계가 없다.**
- **누락 간격:** 직전 수신 frame과의 원본 frame 간격이 4–6(burst 직후)인 frame에서 burst_30 ΔJ −0.0043, burst_50 +0.0015였다. random_50에서 간격이 7 이상인 frame은 7개뿐이다(+0.010).
- **카메라 이동:** 직전 수신 frame 대비 카메라 이동이 0.05 m 이하인 frame(1,725개)에 가장 큰 단일 저하(−0.94, t9)가 있다. 이동이 더 큰 구간의 평균 ΔJ는 0에 가깝다. 큰 실패 두 건 모두 카메라가 정지한 Scene06에서 대상 자체가 움직이거나 가림이 생겨 일어났다.
- **가림:** t86 frame 380(완전 가림)은 누락과 무관하게 실패하는 frame이다. t12의 두 번의 완전 가림 동안 누락 run도 빈 예측을 냈다(오탐 0). 다시 나타난 대상도 정상으로 다시 잡았다. 예외는 random_50 s1이다. 재등장 후인 frame 101(GT 1,200 px)에서 예측이 비었고, 다음 수신 frame 104에서 회복했다.

## 11. 연구 판단

**측정된 결과:**
1. **프레임 누락이 SAM 2 분할 정확도를 크게 떨어뜨리는가? 아니다.**
   - 30–50% 누락에서도 track 평균 ΔJ&F는 −0.0021 ~ +0.0005다(J&F 기준 −0.21 ~ +0.05 point).
   - 계획서가 정책 비교의 성공 기준으로 둔 2.0 point와 비교하면 두 자릿수 작은 값이다.
   - random_30과 burst_50의 ΔJ는 오히려 양수이고 CI도 0보다 크다. 다만 크기는 +0.001–0.002다.
2. **50%가 30%보다 더 나쁜가? 아니다.** random_50(−0.0003)과 burst_50(+0.0005)이 각각 random_30(+0.0005), burst_30(−0.0021)보다 나쁘지 않다. burst_30의 평균은 run 하나(t9 s2)가 결정한다.
3. **burst가 random보다 해로운가?** 평균으로는 일관된 차이가 없다. 다만 유일한 다중 frame 추적 상실은 burst에서 나왔다(4 frame).
4. **대상 크기가 취약성을 설명하는가?** 누락으로 인한 변화는 크기와 무관했다. 정확도 수준은 크기에 좌우된다.
5. **누락 때문에 생긴 진짜 추적 실패가 있는가? 있지만 드물다.** 96개 run 중 2개, 4,681개 보이는 frame 중 6개다. 두 경우 모두 짧은 누락 직후 대상의 외형이 크게 바뀌거나 대상이 일부만 보이는 상황이었다.
6. **회복은 얼마나 자주 필요한가?** burst 사건 393개 중 1개(0.25%)만 누락 직후 J < 0.5였다.
7. **현재 burst_50 설계로 회복을 측정할 수 있는가? 거의 불가능하다.** 관찰 구간 중앙값이 3이고 27.7%가 censoring되며, 회복이 필요한 사건은 0이다.
8. **새 메모리 선택 정책이 개선할 여지는?** 누락 조건의 J&F(0.950–0.953)와 대응 무손실 J&F의 차이는 0.002 이하다. '누락으로 잃은 성능을 되찾는다'는 의미의 개선 여지는 현재 개발 데이터에서 거의 없다. 남은 오차(1 − J&F ≈ 0.05)는 대부분 무손실에서도 생기는 오차(작은 대상, 경계, 부분 가림)이다.
9. **가설은 여전히 유망한가? 현재 설계로는 검증력이 부족하다.**
   - M1: 이동 중 카메라에서 자세 선택 = 최근 선택.
   - M4: 누락이 성능을 거의 떨어뜨리지 않는다.
   - 따라서 recent-K 대비 2.0 point 향상은 이 데이터와 누락 조건에서 달성할 여지가 거의 없다.

**가능한 설명 (가설):**
- SAM 2.1의 메모리(조건 frame + 최근 6개 + object pointer)는 원본 시간으로 몇 frame 정도의 간격에 이미 강건하다. VKITTI의 대상은 프레임 사이 외형 변화가 작다.
- 누락 run에서 ΔJ가 소폭 양수인 경향(96개 중 66개)은 같은 메모리 개수가 원본 시간상 더 넓은 구간을 덮기 때문일 수 있다. 즉 누락이 시간 분산 메모리처럼 작동했을 가능성이다. 검증하지 않았다.

**미해결 질문 / M5 전에 멘토와 결정할 것:**
- 누락 조건을 더 어렵게 만들지: 더 긴 burst(8, 16 frame), 더 높은 누락률, burst 간 최소 간격 확보.
- 대상을 바꿀지: 작은 대상, 가림이 있는 대상, 외형 변화가 큰 대상.
- 데이터를 바꿀지: 재방문·loop 경로, 실제 주행 영상.
- 연구 질문을 바꿀지: '누락 후 회복'에서 '드문 실패 사례 분석'이나 '시간 분산 메모리 자체의 효과'로.
- 이 결정 없이 M5(정책 구현·비교)로 가면 어떤 결과가 나와도 정책 간 차이가 측정 잡음 수준일 것으로 예상한다.

## 12. 제한사항

- 개발 track 8개와 장면 2개뿐이다. CI는 track 수준이며 n이 작다. 시험 장면으로 일반화할 수 없다.
- 실행 환경은 MPS float32이고 CUDA 확장 `_C`가 없다(hole-filling 생략, M2와 같은 조건).
- 무손실 기준은 M2에서 한 번 실행한 결과다. M2에서 MPS와 CPU 결과가 1픽셀 이내로 같았으므로 실행마다 생기는 변동은 무시할 수준으로 본다. 다만 MPS에서 같은 실행을 반복해 재현성을 확인하지는 않았다.
- M3의 결정 사항(seed 0/1/2, 반올림, burst 간격 1)을 그대로 썼다. 회복 지표는 그 결정의 영향을 크게 받는다(6절).
