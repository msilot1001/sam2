# M10 핵심 결론 (우선순위 arm 완료 시점, 2026-10-15 12:45 KST)

**범위**
- dev split만 쓴다: MOSEv2 62단위 / 48영상, VOST 31 / 19, LVOS v2 16 / 12.
- 같은 RunPod RTX 4090에서 SGGL(OR0) 대비 ΔJ&F를 쟀다. 값은 영상 동일 가중이고, CI는 영상 단위 bootstrap 95%다.
- OR0는 M9 SGGL과 frame 단위로 완전히 일치한다.
- 모든 oracle은 GT를 쓰는 **진단용 상한**이다. 실제 방법의 성능이 아니다.

## 1. 결론 한 문장

> SGGL 손실에서 회복 가능한 가장 큰 몫은 **매 frame SAM 2가 이미 만드는 가설 중 무엇을 고르고, 그것을 기억에 쓰느냐**다.
> - 맞는 가설을 골라 출력하고 기억에도 쓰면(OR5M, GT mask 없음) 손실의 60–62%가 회복된다. 이는 GT mask로 기억을 고친 완벽한 기억(OR8, 54–66%)과 같은 수준이다.
> - 이 둘을 함께 쓰면(C58) 76–80%다.
> - 반면 완벽한 crop 기하는 7–13%, 기억 기록 거부는 10–20%, 모델 크기 확대는 유의하지 않다.
> - 따라서 다음에 만들 것은 **GT 없이 맞는 가설을 고르고 그 가설을 기억에 쓰는 가설 검증기**다.

## 5. 한계

- **모두 dev split이다.** conf는 쓰지 않았다(검증기 고정 후 1회 확인용).
- **선택 계열(OR5S, OR5M, C58, C75)과 OR8K10은 LVOS를 돌리지 않았다** (우선순위).
- **OR5M·C58의 '선택'은 GT로 한 것이다.** 실제 검증기가 이 상한의 몇 %를 얻을지는 아직 모른다. 이것이 개선 단계의 질문이다.
- **보류 arm:** OR2, OR3, OR1M, OR6(온라인), OR8C0, C47, C48. 위치·크기 단독 효과와 기하 + 기억 상호작용은 미측정이다.
- **모델 크기 비교는 VOST 한 데이터셋, 2080 한 대에서만 했다.**

## 6. 개선 단계 (진행 중)

1. **OR0F** (수정 4, 12:41 시작): OR0과 같지만 가설별 GT 없는 신호를 기록한다. 신호는 예측 IoU, 면적, 직전 출력과의 IoU·중심 거리, G-L 교차 IoU, frame 0 외형 cosine이다.
2. **오프라인 선택 규칙 비교 (dev):** `m10_analysis.py selector`. 규칙은 SAM 2 예측 IoU, cosine, 시간 연속성, 단순 합, 영상 교차 적합 로지스틱 회귀다.
3. 가장 나은 규칙으로 **검증기 arm**을 고정한다(수정 5). 출력 선택 + 기억 재부호화. dev에서 OR0, 그리고 영 대조(무작위 가설 선택)와 비교한다.
4. 고정 후 **conf에서 1회 확인**한다.
