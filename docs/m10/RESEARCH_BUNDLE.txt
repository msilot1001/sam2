# M10 핵심 결론 (우선순위 arm 완료 시점, 2026-10-15 12:45 KST)

**범위**
- dev split만 쓴다: MOSEv2 62단위 / 48영상, VOST 31 / 19, LVOS v2 16 / 12.
- 같은 RunPod RTX 4090에서 SGGL(OR0) 대비 ΔJ&F를 쟀다. 값은 영상 동일 가중이고, CI는 영상 단위 bootstrap 95%다.
- OR0는 M9 SGGL과 frame 단위로 완전히 일치한다.

## 1. 결론 한 문장

> SGGL 손실에서 회복 가능한 가장 큰 몫은 **매 frame SAM 2가 이미 만드는 가설 중 무엇을 고르고, 그것을 기억에 쓰느냐**다.
> - 맞는 가설을 골라 출력하고 기억에도 쓰면(OR5M, GT mask 없음) 손실의 60–62%가 회복된다. 이는 GT mask로 기억을 고친 완벽한 기억(OR8, 54–66%)과 같은 수준이다.
> - 이 둘을 함께 쓰면(C58) 76–80%다.
> - 반면 완벽한 crop 기하는 7–13%, 기억 기록 거부는 10–20%, 모델 크기 확대는 유의하지 않다.
> - 따라서 다음에 만들 것은 **GT 없이 맞는 가설을 고르고 그 가설을 기억에 쓰는 가설 검증기**다.

1. 프로젝트 배경
----------------------------------------------------------------
목표
  - 작은·극소 객체 semi-supervised VOS. 첫 frame mask가 주어지면 이후 frame을 분할한다.
  - 기반 모델은 동결된 SAM 2.1 Hiera-Tiny(FP32)이며 학습하지 않는다.
  - 그 위에 얹는 추론 wrapper로 성능을 올린다.

현재 기준 시스템: SGGL (M6 이후 계속 1위)
  - G: 전체 frame SAM 2 상태(video predictor)
  - L: 대상 주변의 정사각 crop SAM 2 상태
      · crop 변 = 첫 frame 대상 긴 변 / 0.25, 하한 min(H,W)/4
      · crop 중심은 이전 출력을 따라간다
  - 자기 게이트: L의 점수 > 0이고 L mask가 crop 가장자리에 닿지 않으면 L 출력, 아니면 G 출력
  - 두 상태는 각자 자기 예측을 매 frame 자기 기억(memory bank)에 기록한다(SAM 2 기본 동작)

지금까지 실패하고 중단한 방향
  - M7: mask 융합, 동결 특징 학습 head, 기억 반사실 실험, 조합
  - M8 → M9: crop 위치 운동 운반(FLOWVEL, PCCARRY)
      · DAVIS 계열에서는 이득이 있었다
      · 새 데이터에서는 MOSEv2 −0.014 (CI < 0), VOST +0.005, LVOS −0.002
  - M9: crop 크기 조절(SCALE)
      · 사전 기준 불통과
      · 정보 없는 흔들림(NULLJIT)과 구분되지 않음
  - M9: L 점수 기반 기권(CONSENSUS) — 반증됨(conf −0.050)
  - M8: 후보 생성 + 순위화 rescue
      · 순위화기 AUC 0.57–0.65
      · held-out 순이득 ≤ 0
  - M9 출력 관계 분석: 놓친 손실의 54% / 68% / 68%(MOSEv2 / VOST / LVOS v2)가 '출력이 대상 밖'

M10의 목적
  - GT로 병목 하나씩만 완벽하게 고치는 oracle 개입 실험을 한다.
  - 회복량으로 병목 순위를 정한다.

3. Oracle 정의 (코드: scripts/m10.py)
----------------------------------------------------------------
"후보 7개": 각 frame에서 SAM 2가 이미 만드는 것
  - G 디코더 원시 multimask 가설 3개 (존재 점수로 지우기 전)
  - L 원시 가설 3개
  - 빈 mask
  GT로 새 후보를 만들지 않는다.

  OR1off  존재 판단 (오프라인): GT가 없는 frame의 출력을 비움
  OR4     완벽한 기하: L crop 중심과 크기를 그 frame GT로 설정 (비인과)
  OR5off  후보 선택 (오프라인): frame마다 7개 중 GT J가 최대인 후보. 사후 계산, 미래 영향 없음
  OR5S    후보 선택 (온라인, 출력만): 위 선택을 출력. crop이 출력을 따라간다. 기억은 SAM 2 원래대로
  OR5M    후보 선택 + 기억 (온라인)
          - 출력 = GT 최선 후보
          - 각 view의 frame 기억을 그 view의 GT 최선 원시 가설로 다시 부호화(SAM 2 mask 입력 경로)
          - GT mask는 쓰지 않는다
  OR6off  대상 영역 판별 (오프라인): 맞으면 유지 → 다른 view가 맞으면 교체 → 대상 밖(precision < 0.5)이면 기권
  OR7     기억 기록 허용: view 예측이 맞을 때만 그 view 기억에 기록. 막힌 자리는 이전 frame으로 채운다.
          출력은 SGGL 그대로
  OR7W    대상 밖 예측(precision < 0.5)만 기록 차단
  OR7R    대조: OR7과 같은 개수를 무작위로 차단

9. 지금까지의 결론 (잠정)과 Deep Research에 묻는 것
----------------------------------------------------------------
잠정 결론
  (1) 가장 큰 회복 가능한 병목은 '기억에 들어가는 내용'이다.
      - 완벽한 기억 OR8: 손실의 54–66% 회복
      - 그 대부분은 SAM 2가 이미 만든 가설 중 맞는 것을 고르고 그것을 기억에 쓰면 얻어진다
        (OR5M 60–62%, GT mask 불필요)
  (2) 기록 거부만 하면(OR7) 10–20%만 회복한다.
      - 같은 개수를 무작위로 막는 대조(OR7R)는 0 또는 음수다. 그러니 '어느 frame을 막는지'가 핵심이다.
      - 틀린 것을 막는 것보다 맞는 가설로 바꿔 쓰는 쪽이 3배 이상 크다.
  (2b) GT mask 없이 '맞는 후보 선택 + 틀린 예측 기록 거부'만 완벽하면(C75) 손실의 44–55%를 회복한다.
       실용 검증기의 상한이다. 선택 + 완벽한 기억(C58)은 76–80%다.
  (3) crop 기하(위치·크기)는 완벽해도 7–13%다 → 중단이 타당.
      모델 크기 확대도 VOST에서 유의한 이득이 없다.
  (4) 존재 판단(false_present)은 MOSEv2에서만 크다(손실의 24%, 출력 oracle +0.057).
  (5) 디코더 multimask 가설 선택 오류가 실제로 있다.
      - 예: L의 가설 0이 J 0.93인데 SAM 2가 예측 IoU로 가설 2를 고름
      - 출력 view의 선택 오류(own_view_misselect + suppressed)가 OR0 놓친 손실의 23% (MOSEv2) / 8% (VOST) / 19% (LVOS)

## 3. 오프라인 oracle (OR0 행에서 계산, rollout 없음)

| 이름 | 정의 | 주의 |
|---|---|---|
| OR1off | GT가 없는 frame의 출력을 비움 | 출력만 바꾼다 |
| OR5off | frame마다 7개 후보 중 J 최대인 후보의 J&F | 사후(hindsight). 미래 상태를 개선했다는 주장을 할 수 없다 |
| OR6off | OR6의 출력 규칙을 기록된 G·L mask에 적용 | 기억 효과 없음 |

## 4. 추적 상태 (OR0 frame, GT 기반, 사후)

| 상태 | 정의 |
|---|---|
| correct | GT 있음, J ≥ 0.5 |
| partial | GT 있음, J < 0.5, 출력 precision ≥ 0.5 (대상의 일부) |
| empty | GT 있음, 출력 없음 |
| wrong_region | GT 있음, 출력 precision < 0.5 |
| wrong_object | wrong_region 중 출력의 50% 이상이 **주석된 다른 객체** 위에 있음 (주석된 방해물에 한해서만 '다른 객체'라고 말한다) |
| false_present | GT 없음, 출력 있음 |
| absent_ok | GT 없음, 출력 없음 |

## 5. 통계

- **주 지표:** 데이터셋별로 영상 동일 가중 평균 ΔJ&F(arm − OR0). 단위 평균을 먼저 내고 그다음 영상 평균을 낸다.
- **95% CI:** 영상 단위 bootstrap 10,000회
- **함께 보고:**
  - 하나씩 빼기(LOVO) 최솟값·최댓값
  - 상위 2영상 비중
  - ±0.01 영상 수
  - 극소 단위 ΔJ&F
  - 단위 가중 ΔJ&F
- **회복 비율:** ΔJ&F / (1 − OR0 J&F)
- **데이터셋 처리:** 데이터셋별로 먼저 보고한다. 합산 값은 보조로만 쓴다.
- **JSON 출력:** `allow_nan=False`로 쓴다. 비유한 값은 null이다.

## 4. 핵심 발견

1. **FLOWVEL은 DAVIS 특화였다.**
   - 세 독립 데이터셋 모두에서 평균이 0 근처이거나 음수다.

2. **'스케일' 범주의 실체는 이탈이다.**
   - 스케일 범주 놓친 frame에서 출력 precision 중앙값은 0.07(MOSEv2), 0.00(VOST), 0.36(LVOS v2)이다. '대상 밖'이 59–73%다.

3. **놓친 손실의 절반 이상이 '출력이 대상이 아닌 곳에 있음'이다.**
   - MOSEv2 54%(64영상), VOST 68%(38영상), LVOS v2 68%(18영상)다.
   - 점수 기반 존재 규칙(CONSENSUS)과 순위화(Stage 1 AUC 0.57–0.65)는 이를 가르지 못했다.
4. **단위 수준 결과는 crop 기하에 대해 혼돈적이다.**
   - 정보 없는 ±15% 흔들림만으로 ±0.05 넘는 단위가 8–9개씩 생긴다(MOSEv2 9 / 8, VOST 9 / 7). LVOS v2에서는 −0.05 미만이 3개였다.

5. **값싼 운동 추정은 RAFT를 대신할 수 있지만, 대신할 효과가 없다.** 위상 상관 오차 중앙값은 3 px이고 지연은 1/14이다. 그러나 PCCARRY는 −0.0031이었다.
