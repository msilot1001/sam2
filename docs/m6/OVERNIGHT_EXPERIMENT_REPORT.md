### 4.3 메커니즘 검정 (2·3회차, 사전 고정 규칙)

- **H3 (고정 배율의 메모리 일관성이 중요하다): 지지되지 않음, 결론 불가.**

- **배율 증량 반응: 지지되지 않음.**

  - **너무 좁게 자르면 정지 영상 분할 자체가 나빠진다.** 문맥이 사라지기 때문으로 보인다.

### 4.5 최근접 선행연구 규칙과의 비교 (5회차, A2c)

- **A2c:** CTU 학사논문의 수용 규칙을 같은 틀에 넣었다. 'crop 결과가 전체 frame 결과와 IoU > 0.5'이고 'box 면적 / crop 면적 ≤ 0.1'일 때만 crop을 쓴다.
- **A2x:** crop 상태의 object score > 0이고 내부 경계에 닿지 않으면 crop을 쓴다.

| | A2x (자기 신호 gate) | A2c (일치 gate) |
|---|---|---|
| 작은 객체 ΔJ&F (관문 세트) | +0.018 | +0.010 |
| crop 채택률 (적용 객체 평균) | 0.89 | 0.57 |

- **A2x − A2c = +0.008** [+0.001, +0.014]. A2x가 0.005 이상 나은 객체 5개, A2c가 나은 객체 0개다.
- 가장 큰 차이는 B1이 가장 낮은 lab-coat obj1(극소 대상)에서 나왔다. 나머지 객체의 차이는 B1 수준과 뚜렷한 관계가 없다.

  | 객체 | B1 J&F | A2x − A2c |
  |---|---|---|
  | lab-coat obj1 | 0.75 | +0.040 |
  | mbike-trick obj2 | 0.87 | +0.021 |
  | soapbox obj2 | 0.93 | +0.017 |

- **해석:** 일치 gate는 crop 결과가 전체 frame 결과와 다를 때 crop을 버린다(채택률 0.57). 극소 대상에서는 전체 frame이 틀린 경우가 많아 이 손실이 커진다. 이 결과는 사전 등록한 가설과 같은 방향이다. 다만 **탐색 비교이고 차이는 작다**(+0.008).

### 5.2 부재 감지 vs 분할 정확도 (B1, guitar 제외)

| 세트 | GT 빈 frame | object score AUROC (존재) | 빈 frame 거짓 존재 | 보이는데 놓침 |
|---|---|---|---|---|
| DAVIS val | 55 | 0.998 | 0.0% | 1.1% |
| PUMaVOS A | 238 | 0.994 | 1.7% | 1.5% |
| PUMaVOS B | 6 | 0.9997 | 2/6 | 0.0% |
| SegTrack | 40 | 0.9999 | 0.0% | 0.07% |

- 객체 안에서 계산한 AUROC(GT 빈 frame이 있는 9개 객체): 중앙값 0.994, 최저 0.88.
- GT 빈 frame 중 206/238(PUMaVOS A)은 pimples 한 객체이고, 그 일부는 주석 인공물이다. **'부재 감지 해결'은 이 9개 객체에 한한 관찰**이다.
- 예측 IoU와 J의 Spearman 상관은 0.87이다(보이는 frame).
- 다른 객체를 잡은 frame(other ≥ 30%)은 DAVIS 20개, 나머지 세트 0개다.

### 5.3 판정

- 사전 B3 조건은 '온라인 기회가 있는 실패 4개 이상, 영상 3개 이상'이었다. 결과는 **0개**다.
- **B3를 구축하지 않았다**(규칙대로).
- 부재 감지는 이미 거의 완벽하다. 남은 실패는 작은 대상이나 주석 문제와 겹친다.
- 선행연구(StreamDAM, DAM4SAM, SAMOSA)가 이 영역을 이미 덮는다.
- **검정력 부족 + 선행연구 포화**로 판정한다.

## 6. 트랙 C: 표현·decoder·세부

| 진단 (사후 GT, 상한) | 값 | 사전 규칙 | 판정 |
|---|---|---|---|
| 작은 객체 frame에서 영상 B1 J vs 이미지 oracle(GT box, 최선 3개) | frame 합산 0.776 vs 0.763 (419 frame) / 객체 평균 0.703 vs 0.718 (19개) | — | 대부분의 작은 객체에서 영상이 oracle 수준이다. 예외는 kite-surf obj2(0.18 vs 0.54)와 pimples(0.04 vs 0.19)로, 시간 전파 실패다. GT box oracle은 표현의 상한이 **아니다**(box 자체가 정보를 준다) |
| crop(A1 배율) oracle − 전체 oracle | +0.022 [+0.003, +0.044], 75% 객체 양수 | ≥ +0.05이고 60% | ✗ 입력 배율로 고칠 여지 작음 |
| 256 출력 상한 J < 0.8인 frame | 8.7% (crop 시 0%) | ≥ 25% | ✗ decoder 출력 해상도는 소수(얇은 줄 객체)에만 병목 |
| multimask 후보 최선 − 선택 (frame별, 작은 객체) | +0.008 – 0.014 | — | 후보 선택 여지 작음 |
| **학습 head 파일럿** (4회차, DAVIS train 2 epoch, 8분) | small ΔJ **−0.002** [−0.008, +0.003], 37% 양수 / 보통 ΔJ −0.001 | ≥ +0.05 | ✗ 사전 규칙상 음성. 다만 loss가 0.264 → 0.252로 거의 줄지 않았고 양성 대조가 없다. supervision도 256 해상도라 **결론 불가**에 가깝다 |

**주의:**
- 학습 head 파일럿이 음성이라는 것은 '고정 특징 + 작은 head + 짧은 학습'에서 여지가 없다는 뜻이다.
- SAM2Refiner처럼 다중 scale 특징으로 대규모 학습하는 경우의 여지까지 부정하지는 **않는다**.
- 얇은 줄 객체(paragliding obj3: oracle 0.15, 256 상한 0.24)는 진짜 출력 해상도 한계다. 다만 해당 객체가 3개뿐이다.

## 8. 정확성·누수 점검

| 점검 | 결과 |
|---|---|
| online 경로가 GT를 쓰는가 | 쓰지 않는다. GT는 frame 0 prompt와 평가에만 쓴다. crop 위치는 직전 **출력**에서 정한다 |
| 미래 frame 사용 | 없다. 테스트로 확인했다 |
| A2x에서 전역 출력의 출처 | B1 기록을 다시 읽어 쓴다. B1은 독립적이고 결정론적인 online 실행이므로, frame t 출력을 같은 frame에 쓰는 것은 인과적이다 |
| S1의 arm 전환 | 기록된 arm 궤적을 1회 전환으로 재생한다. 각 arm이 결정론적이고 독립적이라 실제 실행과 정확히 같다. frame별 전환은 하지 않았다(상태가 섞이므로) |
| 좌표 변환 | 메모리는 crop 좌표계에만 있고, 좌표 변환 후 메모리를 재사용하지 않는다. A1v는 배율이 바뀌어도 그 배율 그대로 메모리를 쓴다. 이것이 바로 검정 대상이다 |
| 가중치 | head 파일럿 외에는 바꾸지 않았다. head는 별도 파일 `head_pilot.pt`이고 SAM 2는 그대로다 |
| 학습 데이터 | DAVIS train만 썼다 |
| PUMaVOS C | 실행하지 않았다(테스트로 확인) |
| 다중 비교 | 같은 개발 데이터를 다섯 번 보았다. 어떤 arm이 통과했더라도 C 확인 전까지는 잠정이었을 것이다. 실제로는 통과한 arm이 없다. 영상 bootstrap CI는 관문 세트 영상 10개에 기반하므로 실제보다 좁을 수 있다. A1v의 CI [+0.007, +0.045]는 +0.03을 포함한다 |
| 보통 객체 조건의 약점 | 52개 중 49개가 crop 미적용(Δ = 0)이라 평균이 희석된다. A1은 crop을 적용한 보통 객체 3개 평균이 −0.064인데도 조건을 통과했다. 다음 단계에서는 '적용된 보통 객체' 조건을 따로 둔다 |
| 인과성 테스트 범위 | 테스트는 A1만 직접 확인한다. A1v·A2x·A2c는 같은 코드 경로이지만 별도 테스트는 없다 |
| 업스트림 SAM 2 | 수정하지 않았다(런타임 래퍼만 사용) |

## 10. 기술적 막힘과 한계

- PUMaVOS C의 작은 객체는 2개뿐이다(caps, dog_tail). 확대 방향을 확인하기에 검정력이 거의 없다.
- 극소 대상(< 0.1% 면적)은 개발 데이터에 영상 1개뿐이다. 크기 의존성이 맞는지 확인하려면 새 데이터가 필요하고, 다운로드 승인이 필요하다.
- SAMURAI, SAM2Long, SENTRY는 초록 수준만 확인했다.
- 모든 실험은 Hiera-T로 했다. CTU는 SAM2.1-L을 썼으므로 backbone 크기에 따라 결론이 달라질 수 있다. L checkpoint 다운로드는 승인이 필요하다.
