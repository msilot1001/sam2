# 과제연구 계획서 수정본
멘토링 피드백 반영｜불규칙 프레임 손실 환경에서 촬영 카메라 자세·경과시간 기반 SAM 2.1 메모리 선택

## 1. 탐구 주제
불규칙하게 프레임이 누락되는 주행 영상에서, SAM 2.1이 참조할 과거 메모리를 촬영 카메라의 위치·방향과 실제 경과시간에 따라 선택했을 때 객체 분할 정확도와 누락 후 회복이 개선되는지 검증한다.

이 문서에서 ‘자세(pose)’는 추적 대상 차량의 정답 자세가 아니라 영상을 촬영하는 카메라의 3차원 위치와 방향을 뜻한다. 대상 차량의 GT 위치·자세와 미래 프레임은 입력으로 사용하지 않는다.

## 2. 연구의 필요성과 목적
SAM 2.1은 이전 프레임의 영상 특징과 예측 마스크를 메모리로 저장하고, 이를 현재 프레임의 객체 분할에 활용한다. 일반적으로 최근 메모리는 유용하지만, 주행 영상이 전송 지연·처리 부하·통신 오류로 불규칙하게 누락되면 수신 순서가 가깝더라도 실제 촬영 시점과 시야는 멀 수 있다. 카메라가 이동하거나 회전한 경우에는 더 오래된 프레임이 오히려 현재와 비슷한 시야를 가질 수도 있다.

본 연구는 모델을 다시 학습하거나 메모리 수를 늘리지 않고, 같은 후보 중 어떤 과거 메모리를 선택할지만 바꾼다. 현재 카메라 자세와 비슷한 후보를 찾되 여러 시간 구간에서 고르게 선택하여, 최근 프레임에만 집중되는 문제를 줄일 수 있는지 확인한다.

## 3. 선행연구와 본 연구의 차이
SAM4D는 카메라와 LiDAR 특징을 3차원 공간에서 결합하고 ego-motion을 보정한다. SAM2-Splat은 과거 객체 분할을 온라인 3D Gaussian 메모리로 저장해 현재 분할을 보완한다. Seg2Track-SAM2는 검출기와 SAM 2를 결합해 다중 객체의 시작·연결·관리를 수행하고, sliding-window memory로 메모리 사용량을 줄인다. TSMS-SAM2는 수술 영상에서 여러 시간 간격의 샘플링과 메모리 분할·가지치기를 사용한다.

본 연구는 LiDAR, 3D Gaussian, 추가 검출기, depth 재투영을 사용하지 않는다. 기존 SAM 2.1 Hiera-Tiny의 가중치를 고정하고 RGB 기반 단일 객체 분할에서 메모리 선택 규칙만 비교한다. 핵심 질문은 ‘주행 영상의 불규칙 프레임 손실 상황에서, 고정된 메모리 용량 안에서 카메라 자세와 경과시간을 함께 이용한 선택이 recent-K보다 유리한가’이다. 시간이나 자세를 활용한 최초의 연구라고 주장하지 않고, 동일한 모델·데이터·누락 조건에서 네 선택 정책을 직접 비교해 이 조합의 효과를 검증한다.

## 4. 연구 질문과 가설
### 연구 질문 1
같은 수의 메모리를 사용해도 선택 규칙에 따라 누락 상황의 J&F가 달라지는가?

### 연구 질문 2
시간 분산과 카메라 자세 정보는 각각 어떤 조건에서 도움이 되는가?

### 연구 질문 3
자세와 시간을 함께 사용하면 각각만 사용했을 때보다 누락 후 회복이 빨라지는가?

### 연구 질문 4
대상 차량의 이동 여부, 카메라의 큰 이동·회전, 자세 오차에 따라 효과가 어떻게 달라지는가?

가설은 pose+Δt가 무작위 누락과 연속 누락 조건에서 recent-K보다 J&F와 회복률을 높일 것이라는 것이다. 카메라 움직임이 장면 변화의 주된 원인인 정지 차량에서는 효과가 더 클 수 있고, 대상 차량이 독립적으로 움직이는 경우에는 카메라 자세만으로 현재 시야를 설명하기 어려워 효과가 제한될 수 있다.

## 5. K와 L의 의미 및 설정 근거
K는 현재 프레임을 분할할 때 GPU의 memory attention이 실제로 참조하는 공간 메모리 수다. L은 그 K개를 고르기 위해 CPU에 보관하는 과거 non-conditioning 메모리 후보 수다. 쉽게 말하면 L은 후보 목록의 크기이고 K는 현재 추론에 실제로 꺼내 쓰는 수다.

- K=7: 공식 SAM 2.1 Hiera-Tiny 설정의 num_maskmem 값을 유지한다. 메모리 수 증가가 아니라 선택 규칙의 효과만 보기 위한 통제다.
- 활성 메모리 구성: 최초 프롬프트 메모리 1개 + 가장 최근 수신 메모리 1개 + 정책별 선택 메모리 5개 = 7개다.
- L=32: 최초 프롬프트는 별도로 고정하고, 최근 메모리를 포함한 non-conditioning 후보를 최대 32개 보관한다. 큐가 가득 차면 가장 오래된 후보부터 제거한다.
- L=32는 최적값으로 확인된 값이 아니라 본실험의 초기값이다. 개발 데이터에서 L=16·32·64를 비교해 성능 향상이 작아지는 지점과 CPU 저장·검색 비용을 함께 확인한 뒤 확정한다.
- 초기 구간처럼 후보가 7개보다 적을 때는 가짜 메모리나 중복 메모리를 만들지 않고 사용 가능한 후보만 쓴다. 최초 프롬프트와 최근 메모리가 같은 프레임이면 한 번만 센다.

## 6. 메모리 선택에 사용하는 정보
### 6.1 카메라 자세
Virtual KITTI 2의 카메라 자세는 extrinsic.txt에서 얻는다. pose.txt는 대상 차량의 3차원 정답 정보이므로 메모리 선택 입력으로 사용하지 않는다. 모든 카메라 자세는 같은 좌표계와 변환 방향으로 통일한다. extrinsic이 world-to-camera 형식 Xc=R·Xw+t라면 카메라의 세계 좌표 위치는 p=−Rᵀt로 변환한다.

현재 프레임 t와 과거 후보 i 사이의 이동거리는 dT_i=‖p_t−p_i‖로 계산한다. 상대 회전각 dR_i는 두 회전행렬의 차이로 계산한다. 이동거리와 회전각은 단위가 다르므로 그대로 더하지 않는다.

개발 데이터에서 이동거리와 회전각 분포의 95백분위 sT, sR을 구하고, dT_i'=clip(dT_i/sT,0,1), dR_i'=clip(dR_i/sR,0,1)로 정규화한다. 자세 비용은 C_i=wT·dT_i'+wR·dR_i'이며 wT+wR=1이다. 비용이 작을수록 현재 카메라 자세와 가깝다고 본다. 가중치는 개발 데이터에서 wT=0, 0.25, 0.5, 0.75, 1 후보를 비교해 고르고 시험 데이터에서는 고정한다.

### 6.2 실제 경과시간
Δt는 다시 매긴 수신 순번의 차이가 아니라 원본 촬영 시각의 차이다. Virtual KITTI 2에서 별도 timestamp를 사용하지 못하는 경우에는 원본 프레임 번호 차이를 데이터의 FPS로 나누어 초 단위로 환산한다.

후보의 원본 프레임 경과량을 1~2, 3~5, 6~10, 11~20, 21 이상 다섯 구간으로 나눈다. 구간은 촘촘한 최근 정보와 드문 오래된 정보를 함께 포함하기 위한 초기안이며, 개발 데이터에서만 조정한다. 시간은 자세 비용에 임의의 가중치로 더하지 않고 후보를 구간별로 나누는 데 사용한다. 이렇게 하면 자세 비용과 시간 비용 사이에 또 하나의 자의적인 환산 계수를 만들지 않아도 된다.

## 7. 비교할 네 가지 선택 정책
모든 정책은 최초 프롬프트와 가장 최근 수신 메모리를 공통으로 유지하고, 나머지 다섯 자리만 다르게 고른다. 현재 프레임은 예측과 메모리 인코딩이 끝난 뒤에만 다음 프레임의 후보가 된다.

- recent-K: 가장 최근 메모리를 제외한 후보 중에서 최신 순서로 다섯 개를 고른다. 기본 비교 기준이다.
- time-distributed: 다섯 시간 구간에서 한 개씩 고른다. 닫힌 구간에서는 구간 중앙에 가장 가까운 후보, 21 이상 구간에서는 해당 구간 후보 나이의 중앙값에 가장 가까운 후보를 고른다. 동률이면 최근 후보를 택한다.
- pose-only: 시간 구간을 무시하고 자세 비용 C가 가장 작은 후보 다섯 개를 고른다.
- pose+Δt: 각 시간 구간에서 자세 비용 C가 가장 작은 후보 한 개씩을 고른다.

빈 시간 구간이 있으면 time-distributed는 이미 선택된 시각들과의 최소 간격이 가장 큰 미선택 후보로 자리를 채운다. pose+Δt는 미선택 후보 중 자세 비용이 가장 작은 순서로 채운다. 모든 동률은 더 최근 후보를 우선해 실행마다 결과가 달라지지 않게 한다. 선택한 메모리는 원본 시간순으로 정렬해 같은 방식으로 모델에 전달한다.

## 8. 자료와 실험 조건
- 데이터: Virtual KITTI 2의 clone 변형, 왼쪽 카메라 RGB·instance mask·카메라 extrinsic을 사용한다.
- 개발 장면: Scene 01·06. 가중치, 정규화 기준, 시간 구간과 L을 여기서 정한다.
- 시험 장면: Scene 02·18·20. 개발 단계에서 정한 규칙을 바꾸지 않고 최종 비교에만 사용한다.
- 대상: 첫 프레임 마스크가 전체 영상의 0.1% 이상이고 최소 40프레임 이상 관찰 가능한 차량 track을 사용한다. 장면별 최대 네 track을 사전에 고정한다.
- 프롬프트: 첫 프레임의 GT 마스크만 대상 지정에 사용한다. 이후 GT 마스크는 평가에만 쓴다.
- 본실험 누락 조건: 무손실, 무작위 30%·50% 누락, 길이 4의 연속 누락을 배치해 전체 누락률을 30%·50%로 맞춘 조건을 사용한다.
- 반복: 무작위 위치와 burst 시작점을 세 seed로 미리 생성하고 네 정책이 같은 누락 위치를 공유한다.
- 추가 민감도 분석: burst 길이 2·8, L=16·32·64, 카메라 자세 오차를 시험한다. 본실험과 섞지 않고 별도로 보고한다.

## 9. 변인과 공정한 비교
독립변인은 메모리 선택 정책, 프레임 누락 방식과 누락률이다. 보조 독립변인은 대상 차량의 이동 여부와 카메라 자세 오차다.

주 종속변인은 객체별 J&F다. 보조 종속변인은 burst 이후 회복 프레임 수와 초, 5개 수신 프레임 이내 회복률, J<0.1인 추적 상실률, latency, FPS, peak VRAM, CPU 후보 저장량이다.

통제변인은 SAM 2.1 Hiera-Tiny 체크포인트, 모델 가중치, 입력 해상도와 전처리, FP16, batch size 1, 최초 GT 마스크, 대상 track, 수신 RGB 프레임, 누락 위치와 seed, K, L, 하드웨어다. 네 정책은 같은 수의 RGB 입력과 같은 횟수의 SAM 2.1 forward를 사용한다.

각 정책의 예측 마스크가 달라지면 그 마스크로 만든 이후 메모리 특징도 달라질 수 있으므로, 정책별 메모리는 각각 순차적으로 생성한다. 다른 정책이 만든 예측 메모리를 공유하지 않는다. 무손실 결과와 누락 결과를 비교할 때도 누락 조건에서 실제로 수신된 동일한 프레임 위치만 평가한다.

## 10. 선택 함수와 평가 함수의 구분
자세 비용 C는 추론 중 어떤 메모리를 고를지 정하는 선택 함수다. GT 마스크를 사용하지 않는다. J&F와 회복률은 예측이 끝난 뒤 GT 마스크와 비교하는 평가 지표다. 두 함수는 사용 시점과 목적이 다르다.

평가 지표를 하나의 임의 총점으로 합치지 않는다. J&F·회복 시간·메모리 사용량은 단위가 달라 가중치를 어떻게 주느냐에 따라 결론이 바뀔 수 있기 때문이다. 대신 다음 순서로 판정한다.

1. 주 판정: 같은 누락 조건에서 pose+Δt의 평균 J&F가 recent-K보다 높은지 확인한다. ΔJ&F는 ‘pose+Δt−recent-K’로 정의해 양수가 개선을 뜻하게 한다.
2. 원인 확인: pose+Δt를 time-distributed 및 pose-only와 비교한다. pose-only와 차이가 없으면 시간 분산의 추가 효과가 확인되지 않은 것이고, time-distributed와 차이가 없으면 자세 정보의 추가 효과가 확인되지 않은 것이다.
3. 회복성 확인: burst 종료 뒤 J≥0.5가 두 수신 프레임에서 연속으로 나타났음을 처음 확인한 시점을 회복으로 정의한다. 회복까지의 수신 프레임 수와 실제 경과시간을 함께 기록한다.
4. 실패 처리: 영상 종료나 다음 burst 전까지 회복하지 못한 사건은 평균 회복 시간에서 제외하지 않고 미회복으로 따로 집계한다. 5개 수신 프레임 이내 회복률의 분모는 회복을 판정할 관찰 구간이 확보된 burst 사건으로 고정한다.
5. 비용 확인: 후보 검색·CPU↔GPU 전송을 포함한 전체 프레임 latency, FPS, peak VRAM과 CPU 후보 저장량을 비교한다.

초기 성공 기준은 누락률 30% 이상인 무작위 또는 burst 조건에서 recent-K보다 J&F가 2.0점 이상 높고, paired bootstrap 95% 신뢰구간의 하한이 0보다 크며, 세 시험 장면 중 두 장면 이상에서 같은 방향의 향상이 나타나는 것이다. 동시에 무손실 J&F 하락은 0.5점 이하, 전체 처리 latency 증가는 5% 이하를 목표로 둔다. 이 값들은 이미 얻은 결과가 아니라 실험 전에 정하는 판정 기준이다.

통계 비교는 같은 장면·track·누락 seed를 짝지어 정책 간 차이를 계산한다. seed 결과를 먼저 평균한 뒤 장면과 그 안의 track을 다시 뽑는 paired bootstrap으로 95% 신뢰구간을 구한다. 시험 장면이 세 곳뿐이므로 신뢰구간을 전체 주행 환경에 대한 보편적 증거로 해석하지 않는다.

## 11. 실험 절차
1. 무손실 조건에서 공식 SAM 2.1 Hiera-Tiny의 기본 결과를 재현한다.
2. recent-K에 프레임 누락을 적용해 실제로 성능 저하와 회복 문제가 발생하는지 확인한다.
3. 개발 장면에서 자세 변환, sT·sR, wT·wR, 시간 구간과 L을 정한다.
4. 시험 장면에서 네 정책을 같은 누락 위치로 실행하고 J&F·회복·처리 비용을 측정한다.
5. 대상 차량의 정지·이동 여부, 카메라 이동·회전 크기에 따라 결과를 나누어 본다.
6. L 변화와 자세 오차 민감도 실험을 실시한다.
7. 평균 결과뿐 아니라 정책별 실패 사례와 누락 직후의 시간 흐름을 함께 분석한다.

## 12. 예상 결과와 해석 범위
pose+Δt가 recent-K보다 정확도와 회복률이 높고 pose-only·time-distributed보다도 좋다면 자세와 시간 분산을 결합한 효과를 지지할 수 있다. pose-only와 비슷하면 시간 분산의 추가 효과는 확인되지 않은 것이며, time-distributed와 비슷하면 자세 정보의 추가 효과는 확인되지 않은 것이다. 평균 J&F만 높고 burst 직후 회복 시간이 줄지 않으면 ‘회복 속도를 개선했다’고 주장하지 않는다.

카메라 자세가 비슷하다고 영상 내용이 반드시 비슷한 것은 아니다. 가림·조명 변화·대상 차량의 독립 움직임은 자세 비용에 직접 반영되지 않는다. Virtual KITTI 2의 정확한 카메라 자세는 이상적인 입력이므로 자세 오차 실험이 필요하며, 합성 데이터 결과만으로 실제 도로 성능을 단정하지 않는다.

## 13. 구현 전에 최종 확인할 사항
- SAM 2.1에서 선택한 공간 메모리와 object pointer의 참조 범위를 네 정책에서 동일하게 맞춘다.
- sT 또는 sR이 0에 가까울 때 사용할 최소 정규화 기준값을 정한다.
- 선택 후 메모리의 시간 슬롯 배치가 정책마다 다르게 작동하지 않는지 확인한다.
- latency 측정은 초기화와 예열을 제외하고 같은 프레임 구간에서 반복한다.
- first-failure와 worst-window를 사용할 경우 실패 기준과 구간 길이를 구현 전에 확정한다. 확정하지 못하면 본실험의 핵심 지표에서 제외한다.
